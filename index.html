Not Your Average Vuln Scanner

Supply-chain exposure, from day zero.

NYAVS is an open set of Claude Code skills that assess a newly disclosed vulnerability or supply-chain compromise across your whole build path. It starts as soon as the advisory is published, before commercial scanners ship a detection for it.

> Are we actually exposed — and how do we know?

Why day zero matters

A scanner can only detect what its vendor has written a definition for. NYAVS works from the advisory's own data (CVE, affected versions, IOCs) and checks your environment directly, so the gap between disclosure and detection becomes time spent investigating instead of waiting.

  1. DisclosureAdvisory, research write-up, or supply-chain compromise report is published.
  2. Hour 0NYAVS ingests it: CVEs, affected versions (including appendix tables), IOCs, EPSS, KEV, and exploitation prerequisites.
  3. Same runOne parallel agent per CVE checks source, branches, lockfiles, registries, CI identities, SBOMs, attack surface, logs, and runtime execution.
  4. Same runThe report gives a verdict for every layer, a receipt for every finding, and a list of every coverage gap.
  5. Days laterScanner vendors ship plugins and signatures. NYAVS also reads scanner posture as one input once it exists.

Where it looks

Most of the depth goes into how vulnerable code enters and runs in CI/CD, the layers a host scanner never sees.

01Source & branches

A combined search across code hosts and indexers, which disagree with each other, plus every non-default branch that CI actually builds. A patched default branch can still sit beside a vulnerable release branch.

02Transitive dependencies

Lockfiles are fetched through the hosting API and parsed in memory. That catches packages no manifest names. Nothing is cloned and nothing is uploaded.

03Registry bypass

Artifact-registry pulls are checked against CI jobs that download straight from public registries. A registry miss is never counted as clean.

04CI identities

Which cloud and secrets-manager roles a CI job can obtain, and whether any merge request can reach them. Variable names only, never values.

05Runtime execution

Process telemetry shows which project's CI job or workload actually ran the code, after first checking where the sensor is deployed.

06Everything else

SBOMs, the external attack surface, scanner posture, existing tickets and automation, and a log pivot that drills into raw events before any verdict.

A null is not a clean result

Registries, SBOMs, and lockfiles can all be bypassed or opted out of. Search APIs return confident zeros for capped, rate-limited, archived, unindexed, or wrongly filtered queries. So NYAVS grades every verdict by what would actually have seen the threat.

VerdictWhen
VULNERABLEA vulnerable version is declared or resolved, with a receipt. That includes non-default branches and transitive dependencies.
CONFIRMED_IOC_MATCHAn indicator appears verbatim in a network, authentication, or endpoint field after raw drilldown.
NO_EVIDENCE_FOUNDNothing was found, but the declared layers are bypassable and runtime coverage was partial or missing. The report says which.
NO_COVERAGEThe workload runs where the sensor isn't deployed. That's a gap, not a negative.
NOT EXPOSEDOnly when a runtime source with positive coverage would have seen the threat and didn't.

Silent-zero discipline

Before any zero counts, NYAVS has to show the query could have returned a hit: a positive control, pagination run to the end, caps disclosed, rate limits detected, and filter parameters verified with a nonsense value.

How a run looks

/nyavs-orchestrator CVE-2026-12345

Phase 1-2  intelligence   advisory + appendix + nested sources, EPSS, KEV, prerequisites
Phase 3    exposure       1 agent per CVE: code-search union, branches, lockfiles,
                          registry, CI identity  ->  then SIEM: attack surface, SBOM,
                          scanner posture, tickets, log pivot + raw drilldown, runtime
Phase 4    prioritize     transparent rubric, EPSS reported separately
Phase 5    handoff        STOP: analyst approves the finding package
Phase 6    escalate       STOP: analyst picks formal / advisory / FYI
Phase 7    report         markdown + self-contained HTML, receipts + coverage gaps

Is it practical?

What it is not

  • Not a zero-day discovery tool. It doesn't find unknown vulnerabilities. It needs a published advisory, CVE, or IOCs. Its edge is speed after disclosure.
  • Not complete coverage. No organization has full CI/CD visibility. NYAVS measures your coverage and lists every gap instead of hiding them behind a zero.
  • Not a scanner replacement. It gives an answer before scanners can, checks layers they don't, and reads their posture once it exists.

What it costs you

  • Access. Every platform you don't have (code host, registry, SIEM, runtime sensor) becomes a named gap, and the assessment shrinks accordingly.
  • Setup. Queries are written in a neutral notation with placeholder store names. Plan to map them onto your SIEM before the first run.
  • Agent budget. Parallel agents and many API calls. Expect model costs and code-search rate limits.
  • Judgment. Two STOP gates keep a person in charge of every ticket, post, and escalation.

Status: methodology release

These skills were generalized from a working internal workflow, and every organization-specific detail was removed for publication. This public edition hasn't been run end to end as published. Treat it as a strong starting point to adapt, not a turnkey product.

Install

git clone https://github.com/commandctrl/nyavs.git
cp -r nyavs/skills/* ~/.claude/skills/

# set the variables listed in the orchestrator's Configuration section, then:
/nyavs-orchestrator CVE-2026-12345

Security model

  • Credentials come from environment variables only, and anything that looks like a credential is redacted before any write.
  • Fetched articles and PoC repos are treated as untrusted data, and that boundary is restated inside every sub-agent prompt.
  • Every URL other than the primary advisory passes a VirusTotal check before NYAVS opens it.
  • Repositories are never cloned, and internal inventory is never sent to outside services.
